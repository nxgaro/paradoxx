# Paradox — первая работа из первой задачи

Хакатон, кейс **«The Experience Gap»**, трек **Digital Economy & Future Tech**.

**Один пользователь, одна боль:** выпускник вуза/колледжа Казахстана не может получить
первую работу по специальности, потому что везде требуется опыт, — а опыт не взять
без первой работы.

## Решение

Не «ещё одна биржа вакансий для джунов», а разрез замкнутого круга через **задачу**:

1. Малый бизнес описывает свою боль человеческим языком (форма, без ТЗ).
2. **ИИ-декомпозер** раскладывает боль на scoped-задачи по 2–20 часов с чек-листом приёмки.
3. **Мэтчинг** сверяет профиль навыков студента с задачами и показывает процент совпадения.
4. Закрытая задача попадает в **«Паспорт Paradox»** — верифицированное портфолио:
   задача, артефакт, отзыв бизнеса, часы. Работодатель оценивает работу, а не самооценку.

На сайте работает интерактивное демо мэтчинга (секция «Демо»): выбор навыков →
скоринг против задач малого бизнеса из пилота → ранжирование с объяснением.

## Что уже работает

- Регистрация и вход по email/паролю, серверные сессии в HttpOnly-cookie.
- Личный кабинет с тремя ролями: **Пользователь**, **Потребитель**, **Админ**.
- Потребитель и админ публикуют задачи; пользователь откликается и следит за статусом.
- Потребитель видит отклики на свои задачи, принимает исполнителя или снимает с задачи.
- Админ видит всех пользователей, задачи и отклики, меняет роли через таблицу.
- Смена пароля, защита от self-demotion и удаления последнего админа.
- Демо-мэтчинг на главной подтягивает открытые задачи из базы, с откатом на статический набор.

## Роли

| Роль | Что может |
| --- | --- |
| `user` — Пользователь | Смотрит открытые задачи, откликается, отзывает отклик, видит свои отклики и задачи в работе. |
| `consumer` — Потребитель | Создаёт и редактирует свои задачи, смотрит отклики, принимает/отклоняет исполнителей, завершает задачи. |
| `admin` — Админ | Всё, что умеют остальные, плюс управление ролями, любыми задачами и откликами. |

Новый аккаунт после регистрации получает роль `user`. Роль `consumer` выдаёт админ
в разделе «Пользователи». Свою роль админ изменить не может — защита от потери доступа.

## Стек

- **Фронтенд:** HTML5, CSS (дизайн-токены, без фреймворков), vanilla JavaScript.
- **Бэкенд:** Node.js + Express 4.
- **База:** встроенный `node:sqlite` (`DatabaseSync`), файл `data/paradox.db`. Нативных зависимостей нет.
- **Пароли:** `scrypt` + соль, сравнение через `timingSafeEqual`.
- **Сессии:** случайный токен в SQLite, cookie `paradox_sid` (HttpOnly, SameSite=Lax, 7 дней).
- **В продакшене:** PostgreSQL + pgvector, LLM-декомпозер задач с человеческой модерацией.

## Архитектура

Сайт работает как одностраничник: сервер раздаёт `app.html` на все чистые адреса
(`/`, `/login`, `/match`, `/dashboard`, `/faq`, `/privacy`, `/terms`), а `spa.js`
переключает «виды» внутри одного документа с плавными переходами и реальной
адресной строкой (History API). Старый многостраничный вариант (`index.html`,
`login.html`, `match.html`, `dashboard.html` и отдельные страницы-документы)
остался в репозитории как альтернатива и отдаётся по своим `.html`-адресам.

```
server.js       — Express API, сессии, авторизация, задачи, отклики, админ-эндпоинты, раздача статики
db.js           — схема SQLite, сиды админа и демо-задач
security.js     — scrypt-хеширование паролей и генерация токенов
index.html      — многостраничная версия лендинга (сохранена как альтернатива)
app.html        — весь сайт одним документом: лендинг, вход, подбор, кабинет и страницы-документы как «виды»
spa.js          — клиентский роутер (History API), переходы между видами, вход, подбор и кабинет
login.html/.js  — вход и регистрация, поддерживает возврат через ?next=
match.html/.js  — подбор задачи (навыки → скоринг против задач из БД), доступ только вошедшим
dashboard.html/.js — кабинет: статистика, задачи, отклики, админ-таблица ролей, диалоги
styles.css      — дизайн-система и стили кабинета
paradox.html    — старый автономный билд лендинга, оставлен для истории и не обновляется
```

Адреса: `/` — лендинг, `/login` — вход и регистрация, `/match` — подбор задачи,
`/dashboard` — кабинет. Подбор и кабинет доступны только вошедшим: без сессии
`/match` и `/dashboard` редиректят на `/login`. После успешного входа пользователь
возвращается на исходную страницу (через `?next=`). Старые адреса со `.html`
дают 301-редирект на чистые URL.

Логика ИИ-компонента: профиль навыков пользователя и задачи векторизуются по общим
осям (тег навыков); score = 0.6 * (совпавшие навыки / навыки пользователя) +
0.4 * (совпавшие навыки / навыки задачи). В проде — эмбеддинги вместо тегов,
структура скоринга не меняется.

## Локальный запуск

Нужен **Node.js 22.5+** (из-за `node:sqlite`). Сайт должен открываться через сервер:
при `file://` не работают cookie, API и кабинет.

```bash
npm install
npm start
```

Открыть `http://localhost:3000`. Для разработки с автоперезапуском: `npm run dev`.

При первом запуске создаётся `data/paradox.db`, встроенный админ и демо-задачи.

### Встроенный админ

```
email:    admin@paradox.kz
password: admin123
```

Переопределяется переменными окружения **до первого запуска** (пока база не создана):

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `3000` | Порт сервера |
| `DB_PATH` | `data/paradox.db` | Путь к файлу SQLite |
| `ADMIN_EMAIL` | `admin@paradox.kz` | Email встроенного админа |
| `ADMIN_PASSWORD` | `admin123` | Пароль встроенного админа |
| `ADMIN_NAME` | `Администратор Paradox` | Имя встроенного админа |
| `NODE_ENV` | — | `production` включает `Secure`-cookie |

Пример для Windows PowerShell:

```powershell
$env:ADMIN_PASSWORD = "сложный-пароль"
npm start
```

### Сброс базы

Остановить сервер и удалить `data/paradox.db` — при следующем запуске база и сиды
создадутся заново.

## API

Все ответы — JSON. Аутентификация — cookie `paradox_sid`, выставляется при
`/api/register` и `/api/login`.

### Аккаунт

| Метод | Путь | Доступ | Назначение |
| --- | --- | --- | --- |
| `POST` | `/api/register` | все | Регистрация, роль `user` |
| `POST` | `/api/login` | все | Вход |
| `POST` | `/api/logout` | все | Выход, удаление сессии |
| `GET` | `/api/me` | вход | Текущий пользователь |
| `POST` | `/api/me/password` | вход | Смена пароля |

### Задачи и отклики

| Метод | Путь | Доступ | Назначение |
| --- | --- | --- | --- |
| `GET` | `/api/tasks?status=open` | все | Список задач (фильтр по статусу) |
| `GET` | `/api/tasks/:id` | все | Задача с откликами для владельца/админа |
| `POST` | `/api/tasks` | consumer, admin | Создать задачу |
| `PATCH` | `/api/tasks/:id` | владелец, admin | Изменить задачу или статус |
| `DELETE` | `/api/tasks/:id` | владелец, admin | Удалить задачу |
| `POST` | `/api/tasks/:id/apply` | user, admin | Откликнуться |
| `GET` | `/api/tasks/:id/applications` | владелец, admin | Отклики на задачу |
| `PATCH` | `/api/applications/:id` | владелец задачи, admin | Принять / отклонить отклик |
| `DELETE` | `/api/applications/:id` | автор, admin | Отозвать отклик |
| `GET` | `/api/my/applications` | вход | Мои отклики |
| `GET` | `/api/stats` | вход | Статистика для кабинета |

### Админ

| Метод | Путь | Доступ | Назначение |
| --- | --- | --- | --- |
| `GET` | `/api/admin/users` | admin | Пользователи, роли, счётчики |
| `PATCH` | `/api/admin/users/:id/role` | admin | Сменить роль (`user` / `consumer` / `admin`) |

## Ограничения безопасности

- Пароли не хранятся в открытом виде: `scrypt` с индивидуальной солью.
- Сессии живут 7 дней и удаляются из базы при выходе и по истечении срока.
- Cookie: `HttpOnly`, `SameSite=Lax`, в production — `Secure`.
- Ограничение попыток входа: 10 неудач с одного IP за 15 минут → `429`.
- Сервер раздаёт только файлы из белого списка; `data/`, `node_modules/` и код сервера недоступны.
- Проверка прав выполняется на сервере, а не только скрытием кнопок в интерфейсе.
